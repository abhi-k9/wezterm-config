Leader means press Esc, release, then press the next key.

Reflects the shared .wezterm.lua; local overrides may change shortcuts.

Start here — the leader key

one action per prefix · 2-second timeout

Esc → key activates a terminal action. For example, Esc then c opens a tab. The wave in the tab bar indicates that the leader is active.

Escape changes application input. A single Esc is consumed; timeout does not send it to the app. Press Esc Esc to send one Escape. Unbound keys after the leader are also consumed.

Hold modifiers shown with + together; arrows → between keycaps mean a sequence. “Leader + key” below always means a sequence, not holding Escape.

If that interrupts your editor, use the complete Ctrl+a alternative in the installed copy of wezterm.local.lua. It updates the leader and its double-press forwarding shortcut together.

Panes — split, focus, resize

leader first
Leader Shift+|Split side by side; type the | symbol with Shift held.
Leader -Split into an upper and lower pane.
Leader h / lFocus left / right.
Leader j / kFocus down / up.
Leader ← ↓ ↑ →Adjust the focused pane in that direction by 5 cells.
Leader fShow pane labels; select one to focus.
Leader zZoom the current pane; repeat to restore the split view.
Leader xClose the focused pane, with confirmation. Closing the last pane also closes its tab.
Each resize needs a fresh leader. “Horizontal split” in WezTerm means side by side; “vertical split” means upper/lower.

Tabs & windows

zero-based tabs
Leader cNew tab in the current pane's domain.
Leader b / nPrevious / next tab.
Leader 0 … 9Activate tab index 0–9. Index 0 is the first tab; index 1 is the second.
Ctrl+TabNext tab (built-in).
Ctrl+Shift+TabPrevious tab (built-in).
Ctrl+Shift+nNew window (built-in; Cmd+n on macOS).
Built-in number shortcuts keep their own convention: Ctrl+Shift+1 selects the first tab, while Leader 1 selects the second. The tab bar is always visible at the bottom.

Launchers & workspaces

leader first
Leader pOpen the launcher: profiles, tabs, and workspaces.
Leader wShow the workspace selector.
Leader Shift+?Open the command palette; type a command to find it.
Ctrl+Shift+pCommand palette without the leader.
Leader rReload configuration.
A workspace groups windows, tabs, and panes inside the running multiplexer. It is useful for project separation; it does not save running programs across reboots or an exited multiplexer.

Clipboard & search

system clipboard
Ctrl+Shift+cCopy the selected text.
Ctrl+Shift+vPaste clipboard contents into the focused application.
Leader sSearch scrollback; selected text seeds the query.
Ctrl+Shift+fOpen the same search without the leader.
Ctrl+n / Ctrl+pNext / previous match while the search UI is open.
Ctrl+rCycle the search matching mode while searching.
On macOS, built-in Cmd+c, Cmd+v, and Cmd+f remain available. A terminal application that captures mouse input may require holding Shift to select terminal text.

Copy mode — keyboard selection

built-in mode keys
Leader [Enter copy mode; subsequent keys work inside this mode.
h j k l / arrowsMove left, down, up, right.
v / Shift+vStart a character / whole-line selection.
Ctrl+vStart a rectangular block selection.
g / Shift+gGo to the top / bottom of scrollback.
PageUp / PageDownMove through output one page at a time.
yCopy the selection and leave copy mode.
qLeave copy mode without copying.
These are copy-mode bindings, not shell commands. Copy mode is useful when mouse selection is awkward or you want an exact line/block selection.

Everyday controls

no leader
Ctrl+Shift+=Increase font size (the + key on a US keyboard).
Ctrl+Shift+-Decrease font size.
Ctrl+Shift+0Reset font size to the configured value.
Ctrl+Shift+rReload configuration now; automatic reload also watches saved edits.
Alt+EnterToggle fullscreen (built-in; OS shortcuts can take precedence).
The Ctrl+Shift shortcuts are explicitly configured across platforms. macOS built-in Cmd shortcuts remain enabled. Font-size shortcuts change the current window; edit font_size for the persistent default.

Workflow — editor + shell + logs

  1. Open an editor in the first pane.
  2. Leader Shift+| creates a pane to its right; run your shell commands there.
  3. Leader - splits that pane above/below; run a log watcher in the new pane.
  4. Focus with Leader h/j/k/l or select a pane using Leader f.
  5. Leader z enlarges a pane temporarily. Repeat to return to the layout.

Workflow — find & copy output

  1. Leader s opens search. Enter a term, then navigate matches with Ctrl+n / Ctrl+p.
  2. For precise keyboard selection, enter copy mode with Leader [.
  3. Move to the text; press v for characters or Shift+v for whole lines, then extend the selection.
  4. y copies and leaves copy mode. Paste with Ctrl+Shift+v, or Cmd+v on macOS.

Scrollback is limited by scrollback_lines; increasing it retains more output per pane and uses more memory.

Workflow — separate projects

  1. Leader w opens the workspace selector. Choose an existing workspace or its create-workspace entry.
  2. The create entry assigns a name automatically. From a pane in that workspace, run wezterm cli rename-workspace project to choose a meaningful name.
  3. Leader c adds a tab. Use Leader b / n to switch tabs.
  4. Leader p shows profiles, tabs, and workspaces together.

Workspace names and layouts belong to the running mux. Use a separate session manager if you need explicit persistence or program restoration.

Portable setup & private profiles

shared defaults · optional local layer

Clone into ~/wezterm-config on Linux/macOS or %USERPROFILE%\wezterm-config on Windows. Copy the shared config to the home-directory location below; cloning alone does not activate it. The setup guide has OS-specific install, backup, and update commands.

Windows%USERPROFILE%\.wezterm.lua
%USERPROFILE%\wezterm.local.lua (optional)
Linux / macOS~/.wezterm.lua
~/wezterm.local.lua (optional)

Test a chosen configuration explicitly:

wezterm --config-file /path/to/.wezterm.lua show-keys --lua
wezterm --config-file /path/to/.wezterm.lua start

Shell selection: Linux and macOS use the user's normal shell. Windows uses native Windows shells; the launcher offers Windows-only entries only on Windows. A separately installed shell can be selected in the local file.

Machine-only tools: copy the repository's commented wezterm.local.lua beside your installed home-directory .wezterm.lua, then edit that copy. The repository file is a tracked public example; it enables no overrides by default.

The local file returns function(config, wezterm) and runs after shared settings. Append profiles to config.launch_menu there, guarded by the platform or tool availability. Keep machine paths, internal identifiers, and credentials out of tracked files.

Updates: pull the checkout with git pull --ff-only, then copy its .wezterm.lua to your home directory again. Keep wezterm.local.lua in place; shared updates do not replace it. Private profiles come from your own storage and are not included in the repository.

If using a different config directory, place the private copy inside the active wezterm.config_dir outside this checkout. After creating it for the first time, manually reload with Ctrl+Shift+r or Cmd+r on macOS. If you kept an ignored private file at the checkout root on an older version, move it out before pulling this change. Check Git status before committing.

Command-line reference

use an installed wezterm executable
wezterm --config-file /path/to/.wezterm.lua show-keys --luaLoad that configuration and inspect its effective bindings, including defaults.
wezterm --config-file /path/to/.wezterm.lua ls-fontsInspect actual font resolution and fallbacks.
wezterm start --cwd /path/to/projectOpen a terminal in a chosen directory.
wezterm start -- program argRun a specific program instead of the default shell. Use native quoting for your shell.
wezterm cli listList windows, tabs, and panes in a running local instance.
wezterm cli split-pane --right
wezterm cli split-pane --bottom		Create a right-side / lower pane from inside WezTerm.
wezterm cli spawn --new-window --workspace projectCreate a window in a named workspace in the running mux.
wezterm cli rename-workspace projectRename the workspace containing the current pane.
CLI pane commands can target another pane with --pane-id ID. A workspace is not a guarantee of process persistence; closing its multiplexer ends the associated processes.
