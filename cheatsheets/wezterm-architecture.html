Give each layer a role

WezTerm: native windows, fullscreen, fonts, and deliberate outer-terminal controls.

Zellij: inner terminal panes/tabs, sessions, and their per-pane scrollback.

Neovim: editing, buffer navigation, and editor splits/mappings.

The outer APP/WEZ badge and inner Zellij lock indicator describe independent state. Their toggles are different keys.

Displayed nesting and terminal objects

Window-local mode state

APP activates no outer control table. WEZ activates the explicit wezterm table; the two-second one-shot prefix temporarily activates wezterm_commands.

Unknown keys fall through. There is no native config.leader, so bare Escape is never a hidden global prefix. F12 is available to Zellij in both modes and during a pending prefix.

New windows start APP. Changing tabs inside a window keeps that window’s mode; reload clears table state back to APP. No process detection or Zellij-lock synchronization is used.

Keep the outer retro tab bar visible for the badge. WezTerm copy/search/picker UIs can temporarily own their UI keys; toggling APP closes copy/search.

Closing scope and persistence

Neovim quitEnds an editor window/application scope; a parent shell can remain.
Inner pane / tabZellij ends the selected inner terminal(s). Other inner panes/tabs are separate scopes.
Zellij detachDisconnects a client while the session/server can continue.
Outer pane / tabWezTerm closes that outer terminal scope and disconnects any Zellij clients it hosts. Last-pane/tab closes cascade to their parent objects.
Native windowCloses all its outer tabs. Other windows are separate scopes.
Application quitExits the GUI application; distinct from closing one window, particularly on macOS.

Zellij session survival depends on its server and on_force_close setting; the companion shared config chooses detach. A separate WezTerm mux server or remote domain has its own lifetime. Workspace names and Lua files are not application checkpoints. See the closing workflow.

Three different views of history

Neovim navigates buffers and editor views. Zellij retains history for individual inner terminal panes. WezTerm sees the rendered outer client stream.

The right-edge WezTerm bar controls the active outer pane’s viewport. It cannot expose a specific inner Zellij pane’s independent history. Full-screen TUIs often use an alternate screen that does not contribute to normal outer scrollback.

The shared outer history limit is 10,000 lines per pane. Discarded history cannot be recovered by scrolling, and history is not a durable log.

Use Zellij Scroll mode for inner build/shell output. Use WEZ paging/copy mode for direct outer-shell history. Scrolling workflow.

Clipboard and key encoding are separate concerns

APP forwards input using the normal terminal protocol; it does not forward raw USB events or promise every Ctrl/Shift combination is distinguishable. OS-reserved shortcuts can act before WezTerm.

Clipboard writes from inner applications can use a configured provider/OSC52 path. WezTerm’s own copy/paste controls act on the host clipboard and rendered outer selection.

This repo does not configure Neovim clipboard integration, change the keyboard protocol, or disable mouse/native window controls. See clipboard setup and limits.

Confirmation, exit, and lock mean different things

Outer pane/tab actions request confirmation; native window close uses window_close_confirmation. skip_close_confirmation_for_processes_named can exempt idle/safe processes.

CloseOnCleanExit holds failed outer processes for inspection. A held pane need not have a live process. A mode called Locked changes key handling; it is not a save, detach, or process checkpoint.

WezTerm confirmation does not guard an inner Zellij close. Save editor data before closing any scope.

Configuration, domains, and workspaces

The tracked .wezterm.lua is copied to the active home-directory location. An optional adjacent wezterm.local.lua runs last; the repository version of that file is a commented public no-op example.

Private menu entries stay in the installed copy. A launch profile describes a command, not saved session state. Outer workspaces group WezTerm windows; Zellij sessions group their own inner work.

A WezTerm execution domain chooses a local/optional remote backend. Outer new tabs/splits follow CurrentPaneDomain. Domains and workspaces are independent of APP/WEZ and Zellij lock state.

Defaults are disabled and native leaders rejected to preserve APP routing. Add outer shortcuts to config.key_tables.wezterm; additions to global config.keys also capture keys in APP. OS setup · full input contract.
