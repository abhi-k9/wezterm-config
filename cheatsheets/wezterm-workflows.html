Finish work and close the intended scope

  1. Save changes in the applications you want to stop. Focus the pane or tab you intend to close; use Leader f if the active pane is unclear.
  2. For one pane, press Esc → x. To finish a shell normally instead, enter exit at its prompt. Exiting a nested shell or an editor can return to the parent program rather than remove the pane.
  3. For an entire tab, press Ctrl+Shift+W, or Cmd+W on macOS. This closes every split in that tab, not just the focused pane.
  4. For the whole window, click its native close button. Check all its tabs first. On Windows, Alt+F4 requests the same window-level close.
  5. Respond to any confirmation prompt. A safe/idle shell may close immediately even though confirmation is enabled.

In the default local setup, closing sessions ends their associated terminal programs; it is not a detach/save operation. To put a project aside while it continues running, switch workspaces instead. See lifetime and persistence for remote/separate-mux considerations.

Workflow — editor + shell + logs

  1. Open an editor in the first pane.
  2. Leader Shift+| creates a pane to its right; run your shell commands there.
  3. Leader - splits that pane above/below; run a log watcher in the new pane.
  4. Focus with Leader h/j/k/l or select a pane using Leader f.
  5. Leader z enlarges a pane temporarily. Repeat to return to the layout.

Read long output and scroll fast

  1. Focus the pane containing the output. Its scrollbar is at the window's right edge; drag the thumb to move through its history.
  2. For quick keyboard paging, hold Shift and press PageUp / PageDown. On a compact Mac keyboard, use Shift+Fn+↑ / Shift+Fn+↓.
  3. For long jumps without page keys, enter copy mode with Esc → [. Use Ctrl+b / Ctrl+f for pages, or Ctrl+u / Ctrl+d for half-pages.
  4. Press g for the oldest retained output, or Shift+g for the newest. Press q to leave copy mode.
  5. To resume following live output, jump to the newest output before leaving copy mode, or type at the shell prompt: scroll_to_bottom_on_input = true returns the viewport to the bottom on input.

For a specific error, use search instead of repeated paging: Leader s, then Ctrl+n / Ctrl+p between matches. The complete bindings are in keymap: scrolling.

If the bar is missing after updating, copy the new shared .wezterm.lua into your active home-directory location and reload. Check for a local enable_scroll_bar = false override. History limits and full-screen app behavior are covered in architecture: scrollback.

Workflow — find & copy output

  1. Leader s opens search. Enter a term, then navigate matches with Ctrl+n / Ctrl+p.
  2. For precise keyboard selection, enter copy mode with Leader [.
  3. Move to the text; press v for characters or Shift+v for whole lines, then extend the selection.
  4. y copies and leaves copy mode. Paste with Ctrl+Shift+v, or Cmd+v on macOS.

Scrollback is limited by scrollback_lines; increasing it retains more output per pane and uses more memory.

Workflow — separate projects

  1. Leader w opens the workspace selector. Choose an existing workspace or its create-workspace entry.
  2. The create entry assigns a name automatically. From a pane in that workspace, run wezterm cli rename-workspace project to choose a meaningful name.
  3. Leader c adds a tab. Use Leader b / n to switch tabs.
  4. Leader p shows profiles, tabs, and workspaces together.

Workspace names and layouts belong to the running mux. Use a separate session manager if you need explicit persistence or program restoration.

Use a machine-only launch profile

  1. Install the shared config using the OS setup guide.
  2. Copy the tracked, commented wezterm.local.lua into your home directory beside the active .wezterm.lua. Keep an existing private file rather than replacing it.
  3. Edit only the installed copy. Add a config.launch_menu entry guarded by the platform and the availability of its local initialization script.
  4. Reload with Ctrl+Shift+r, or Cmd+r on macOS. Open Leader p and select the profile.

A missing local file is allowed. The repository copy is a public no-op example. Private paths and commands belong outside the checkout; a machine without the required tools should omit that launch entry.

A process exited but its pane stayed open

  1. Read the exit message and retained output. The shared exit_behavior = 'CloseOnCleanExit' keeps failed processes visible for diagnosis.
  2. Fix the command or its local profile if required. A held pane does not mean its command is still running.
  3. Dismiss that pane with Leader x, then open a new tab/pane or select the corrected profile.

Interrupting an application is different from closing its terminal. At a shell, Ctrl+C normally interrupts foreground work and leaves the shell open; it does not replace the close commands.

Update settings without replacing private overrides

  1. For a shared update, follow the update instructions: pull the checkout and copy its .wezterm.lua to the active home-directory location.
  2. Leave your installed wezterm.local.lua in place. Edit personal font/shell/leader preferences there.
  3. Reload and check for configuration errors. Initial rows/columns affect new windows; they do not resize an existing window on reload.

Creating the optional local file for the first time may require a manual reload. Existing files are watched for edits. Changing settings does not restart already running applications.

Command-line reference

use an installed wezterm executable
wezterm --config-file /path/to/.wezterm.lua show-keys --luaLoad that configuration and inspect its effective bindings, including defaults.
wezterm --config-file /path/to/.wezterm.lua ls-fontsInspect actual font resolution and fallbacks.
wezterm start --cwd /path/to/projectOpen a terminal in a chosen directory.
wezterm start -- program argRun a specific program instead of the default shell. Use native quoting for your shell.
wezterm cli listList windows, tabs, and panes in a running local instance.
wezterm cli split-pane --right
wezterm cli split-pane --bottom		Create a right-side / lower pane from inside WezTerm.
wezterm cli spawn --new-window --workspace projectCreate a window in a named workspace in the running mux.
wezterm cli rename-workspace projectRename the workspace containing the current pane.
CLI pane commands can target another pane with --pane-id ID. A workspace is not a guarantee of process persistence; closing its multiplexer ends the associated processes.
